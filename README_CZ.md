# Robot Cockpit — ROS 2 Ground Control

Android application written in Kotlin + Jetpack Compose. The current build is a ROS 2 ground-station prototype with a real rosbridge WebSocket transport (not a simulated connection).

## Current capabilities

- Connect to a ROS 2 robot through a ROS 2 compatible rosbridge_server over WebSocket.
- Subscribe to nav_msgs/OccupancyGrid, sensor_msgs/LaserScan, nav_msgs/Odometry and sensor_msgs/BatteryState.
- Render occupancy map, LiDAR scan and robot pose together.
- Send geometry_msgs/Twist to the configured velocity topic.
- Send a geometry_msgs/PoseStamped navigation goal to the configured goal topic when a map is available.
- Configure the WebSocket URL and topic names in the app; settings are saved on the device.
- Telemetry and connection events are shown in the app.

## Requirements on the robot

1. ROS 2 and the robot's normal drivers/navigation stack must already be running.
2. Install and run a ROS 2 compatible rosbridge_server (typically rosbridge_websocket on port 9090).
3. Make the WebSocket endpoint reachable from the phone over Wi-Fi or another trusted network.
4. Confirm actual topic names and message types using ros2 topic list and ros2 topic info <topic>.
5. Configure the app's URL and topics to match the robot.

Defaults are /map, /scan, /odom, /battery_state, /cmd_vel, and /goal_pose. Your robot may use different names or namespaces.

## Safety

- The app starts disarmed. Motion commands are only sent while connected and locally armed.
- Releasing the joystick sends a zero Twist command; STOP sends a zero command and locally disarms.
- This is NOT a safety-rated emergency stop. Network loss, Android suspension, or a robot-side controller that holds the last command can defeat software-only stopping. Configure a robot-side command timeout/watchdog and retain a physical emergency stop.
- Test with drive wheels lifted or motors disabled first. Start with very low speed limits.
- The app does not invent demo telemetry. Missing ROS messages are shown as missing data.

## Not implemented yet

- Native ROS 2 DDS from Android.
- MAVLink / ArduPilot vehicle connection, arming, flight modes, mission upload, GPS HUD, and parameter management.
- Nav2 action client for full NavigateToPose feedback/cancel; this version publishes a PoseStamped goal topic, which must match the robot's navigation setup.
- Authenticated TLS configuration and reconnection/backoff policies suitable for production.

The APK build is generated by GitHub Actions on pushes to main; download the RobotCockpit-debug-APK artifact from the successful workflow run.
